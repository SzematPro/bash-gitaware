# Wave 9 review

- Date: 2026-11-27
- Scope: T9.1 to T9.4 (key table, completion, `config list --all`)
- Lens: correctness and compatibility (one reviewer with shell, Docker and
  pty access). No SR: the wave adds no input from repositories or other
  users.

The validator refactor was checked against 3.1.0 on 21 keys and about 95
values, in four locales and under several shell options, on bash 4.4 to
5.3. The behavior is the same for every input a caller can pass.

| ID | Finding | Ruling |
|---|---|---|
| W9-1 (major) | With a key on two valid lines, the loader kept the first while `list --all` (and `config get`) named the last | Fixed: the last valid line wins in the loader, consistent with `get` and `set`; CHANGELOG "Changed"; test |
| W9-2 (major) | `list --all` re-read the config file, so a file the loader refused, or an edit not yet reloaded, was named as the source | Fixed: the loader records each value's source and value at load; `list --all` reports those; tests (refused file with a preset) |
| W9-3 | A value changed in the shell after load kept its old source | Fixed: a value that differs from the recorded one is `environment`; test |
| W9-4 | Completion used `COMP_WORDS`, so quoted words and a cursor inside a word did not complete | Fixed: uses `$2` (dequoted, cut at the cursor); pty test inside double quotes |
| W9-5 | A space after a comma-list item | Fixed: `nospace` for list items. A `COMP_WORDBREAKS` that contains `,` is not supported (non-default) |
| CI | With the policy fixtures, a policy value that replaced an exported variable was reported as `environment` | Fixed: sources are recorded after the policy variables join the managed set |

Rulings pass: no new ruling.
