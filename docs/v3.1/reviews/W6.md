# Wave 6 review

- Date: 2026-11-25
- Scope: `v3.1-w5..979d9c7` (T6.1 to T6.7), plus the fixes that followed
- Lenses: correctness and compatibility (one reviewer with shell and Docker
  access), and security, which is SR5 ([SR5.md](SR5.md)).

No blocker. Every finding was reproduced before it was ruled on.

| ID | Finding | Ruling |
|---|---|---|
| W6-1 (major) | A root-only (0600) policy was reported as applied, locked nothing, and printed a raw `Permission denied` in every shell; `doctor` exited 0 | Fixed in 153d27a: an unreadable policy is refused with a reason (fixture and test added); `(locks: none)` for an empty policy |
| W6-2 | `bga reload` kept values from a removed or refused policy. The underlying 3.0 bug: values loaded from the config file counted as environment on reload, so `bga theme set X; bga reload` kept the old theme | Fixed in 153d27a: values bash-gitaware assigned are recorded and unset before a reload; regression tests for the 3.0 bug and for a policy that goes away |
| W6-3 | Locking `nerd_font` does not lock the glyph set (`glyphs` has priority), and a locked `preset` only sets defaults | Documented in ADR-0011 ("What a lock covers"): lock `glyphs` for the glyph set |
| W6-4 | On Linux the `getfacl` branch never mattered: POSIX ACL write entries raise the mask, which shows as group write. Its only effect was refusing masked entries that grant nothing | Fixed in 153d27a: the branch is dropped and the reason is in ADR-0011. The macOS ACL check stays, because macOS ACLs do not show in the mode bits |
| W6-5 | `tests/policy-fixtures.sh` reset `/opt` to 755 | Fixed: fixtures moved to `/etc/bga-policy-test`. CI also showed that hosted Ubuntu runners give their user an ACL write grant on `/opt`, which made every `/opt` fixture correctly untrusted |
| CI | The first CI run of the policy failed on Ubuntu for the reason in W6-5 | Fixed by the same move |

Rulings pass: no new ruling. The threat model and the decisions are in
ADR-0011.
